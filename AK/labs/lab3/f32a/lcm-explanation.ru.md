# Объяснение кода: `lcm.s` (f32a)

Программа вычисляет НОК (наименьшее общее кратное) двух положительных чисел `a` и `b`:

```
lcm(a, b) = (a / gcd(a, b)) * b
```

где `gcd` — наибольший общий делитель, вычисляемый алгоритмом Евклида (`a mod b`).
Если `a <= 0` или `b <= 0` — результат `-1`. Если итоговое произведение не помещается
в 32-битное слово со знаком — результат `0xCCCCCCCC`.

f32a — стековая архитектура (вдохновлена GreenArrays F18a): основное хранилище
операндов — это стек данных (`T` — вершина, `S` — следующий элемент), плюс два
регистра общего назначения `A` и `B`, плюс отдельный стек возврата (для адресов
возврата из процедур и для счётчика циклов `next`).

## Данные

```
input_addr:   .word 0x80
output_addr:  .word 0x84
divisor_ptr:  .word 0x88      \ scratch RAM address used by +/ as mem[B]

a_val:        .word 0x00
b_val:        .word 0x00
wa:           .word 0x00      \ working copies, mutated by the gcd loop
wb:           .word 0x00
g_val:        .word 0x00
```

- `input_addr`/`output_addr` — обычная для wrench пара констант-указателей: ячейки
  хранят *значения* `0x80`/`0x84` (адреса memory-mapped IO портов), а не сами
  являются этими портами.
- `divisor_ptr` — отдельная константа-указатель на ячейку `0x88`. Она не описана
  как `.word` в `.data` намеренно: это просто "сырой" байт памяти, который инструкция
  `+/` (шаг деления) читает как `mem[B]` — делитель. Такой же приём используется в
  `test/golden/f32a/div.s`.
- `a_val`/`b_val` — исходные `a` и `b`, сохраняются один раз и больше не меняются
  (они снова понадобятся в конце для `a / gcd` и для умножения на `b`).
- `wa`/`wb` — "рабочие" копии, которые мутирует цикл Евклида. Они отделены от
  `a_val`/`b_val`, потому что сам НОД процесс уничтожает исходные значения, а они
  нужны позже неизменными.
- `g_val` — куда кладём финальный `gcd(a, b)` после выхода из цикла.

## Точка входа

```
    .org 0x100                \ keep code clear of the IO cells and the divisor scratch cell

_start:
    @p input_addr a! @ @      \ two reads: first is a, second is b
    !p b_val
    !p a_val
```

`.org 0x100` отодвигает код подальше от IO-портов (`0x80`/`0x84`) и от "сырой"
ячейки делителя (`0x88`), чтобы байты инструкций физически не легли поверх этих
адресов (как в acc32-лабе, где без этого словили `instruction in memory corrupted`).

Чтение входа: `@p input_addr a!` кладёт на стек данных значение из `input_addr`
(то есть `0x80`), и `a!` переносит его в регистр `A` — теперь `A = 0x80`, адрес
входного порта. Дальше `@ @` — это **два** чтения `mem[A]` подряд. Каждое чтение
из memory-mapped IO-адреса потребляет следующий элемент из списка, заданного в
`memory_mapped_io: 0x80: [a, b]` конфига — поэтому первое `@` читает `a`, второе — `b`.
После `@ @` стек: `b(верх) a(низ)`.

`!p b_val` снимает верхний элемент (`b`) и кладёт его в `b_val`. `!p a_val` снимает
оставшийся элемент (`a`) и кладёт в `a_val`. Стек снова пуст.

## Проверка домена

```
    @p a_val inv 1 + -if domain_fail   \ negate + nonneg-test
    @p b_val inv 1 + -if domain_fail
```

В ISA нет готовой инструкции "меньше или равно". Есть только `if` (переход, если
вершина стека равна нулю) и `-if` (переход, если вершина **неотрицательна**).
Поэтому проверка `a_val <= 0` делается через отрицание числа и тест на
неотрицательность: `inv 1 +` превращает `a_val` в `-a_val` (дополнение до двух:
`~x + 1 = -x`), а `-a_val >= 0` истинно ровно тогда, когда `a_val <= 0`. Если
условие верно — переход на `domain_fail`. Та же проверка повторяется для `b_val`.

## Подготовка рабочих копий и цикл Евклида

```
    @p a_val !p wa
    @p b_val !p wb

gcd_loop:
    @p wb if gcd_done
    @p wa @p wb divmod drop
    @p wb !p wa                \ wa <- old wb
    !p wb
    gcd_loop ;
```

`wa`/`wb` инициализируются из `a_val`/`b_val`. Дальше — классический цикл Евклида:
`while wb != 0: wa, wb = wb, wa mod wb`.

- `@p wb if gcd_done` — если `wb == 0`, НОД найден (он лежит в `wa`), выходим из цикла.
- `@p wa @p wb divmod drop` — кладём на стек `wa` и `wb`, зовём процедуру `divmod`
  (см. ниже), она возвращает пару `[частное(верх), остаток]`; `drop` убирает частное,
  остаётся только остаток `wa mod wb`.
- `@p wb !p wa` — **важно**: сначала читаем *старое* значение `wb` и кладём его в
  `wa`, и только **после этого** следующей строкой перезаписываем `wb`. Если бы
  порядок был обратный, `wb` уже содержал бы новый остаток к моменту, когда мы
  пытаемся прочитать "старое" значение для `wa` — значения потерялись бы.
- `!p wb` — кладёт ранее вычисленный остаток в `wb`.
- `gcd_loop ;` — это **переход** (`;` после метки = Jump, а не Call), а не вызов
  процедуры, так что стек возврата не трогается.

## Вычисление результата и вывод

```
gcd_done:
    @p wa !p g_val

    @p a_val @p g_val divmod swap drop  \ divmod leaves [q,r]
    @p b_val
    mul_sat

    @p output_addr a! !
    halt

domain_fail:
    -1
    @p output_addr a! !
    halt
```

`gcd_done` копирует итоговый `wa` (НОД) в `g_val`. Дальше:

- `@p a_val @p g_val divmod` — считаем `a_val / g_val`. `divmod` снова отдаёт
  `[частное(верх), остаток]`; на этот раз нужно частное, а не остаток, поэтому
  `swap drop` (своя процедура `swap`, см. ниже) меняет местами верхние два
  элемента и дропает уже не нужный остаток — остаётся только частное `q`.
- `@p b_val` кладёт `b_val` на стек — теперь стек `b_val(верх) q(низ)`.
- `mul_sat` перемножает их и либо возвращает честное произведение, либо
  `0xCCCCCCCC`, если оно не влезает в 32-битное слово со знаком (см. ниже).
- `@p output_addr a! !` — по уже знакомой схеме (`a!` ставит `A` на адрес порта
  вывода `0x84`, `!` пишет туда значение с вершины стека) результат уходит в IO.
- `domain_fail` — отдельная ветка: кладёт `-1` и пишет его в тот же выходной порт.

## Процедура `swap`

```
swap:
    over >r >r drop r> r>
    ;
```

В ISA нет встроенного `swap`, поэтому он собран из того, что есть — через
временное хранение на стеке возврата (`>r`/`r>`). Для входа `[y(верх) x]`:
`over` дублирует `x` наверх → `[x y x]`; `>r >r` переносит `x`, затем `y` на
стек возврата (в таком порядке, что `R = [y, x]`, `y` сверху); `drop` убирает
оставшийся `x` с основного стека; `r> r>` возвращает `y`, затем `x` обратно —
итог `[x y]` на стеке данных, то есть операнды поменялись местами.

## Процедура `divmod`

```
divmod:
    @p divisor_ptr b!
    !b
    a!
    0 0
    31 >r
divmod_loop:
    +/
    next divmod_loop
    ;
```

Стек-эффект: `( dividend divisor -- quotient remainder )`. Это тот же приём, что
в `test/golden/f32a/div.s` — 32-шаговое "восстанавливающее деление" через
инструкцию `+/`.

- `@p divisor_ptr b!` ставит `B` на адрес `0x88`.
- `!b` снимает верхний элемент стека (делитель) и кладёт его в `mem[B]` — именно
  туда, откуда `+/` будет его читать на каждом шаге.
- `a!` снимает оставшийся элемент (делимое) в регистр `A`.
- `0 0` — начальные накопители частного и остатка на стеке.
- `31 >r` + `next` даёт ровно **32** повторения `+/` (цикл `next` выполняет тело
  `R+1` раз: при `R=31` тело выполнится 32 раза, что и нужно для 32-битного слова).
- После цикла инструкция `+/` на каждом шаге сама кладёт на стек `[частное(верх),
  остаток]`, так что `;` просто возвращает этот результат вызывающему коду.

## Процедура `mul_sat`

```
mul_sat:
    a!
    0
    31 >r
mul_sat_loop:
    +*
    next mul_sat_loop
    swap drop                  \ +* pushes S then T, so T ends up on top, not S
    if mul_sat_checklow
    0xCCCCCCCC
    mul_sat_done ;
mul_sat_checklow:
    a                          \ mres-low; its sign bit decides overflow since mres-high was 0
    dup -if mul_sat_ok
    drop 0xCCCCCCCC
    mul_sat_done ;
mul_sat_ok:
mul_sat_done:
    ;
```

Стек-эффект: `( x y -- result )`. Это умножение методом "сдвиг-и-сложение" через
инструкцию `+*`, как в процедуре `multiply` из `factorial.s`, но с одним важным
отличием: `factorial.s` после цикла просто **выбрасывает** старшее слово
произведения (`drop drop a`), получая обычное 32-битное умножение с тихим
переполнением. `mul_sat` вместо этого **проверяет** старшее слово — и если
результат не влезает в 32 бита со знаком, возвращает `0xCCCCCCCC`.

- `a!` переносит `y` в регистр `A` (множимое, которое `+*` будет побитово сдвигать).
- `0` кладёт начальный аккумулятор старшего слова; `x` остаётся под ним на стеке.
- 32 шага `+*` (тот же приём `31 >r` + `next`) строят полное 64-битное
  произведение: младшие 32 бита оказываются в регистре `A`, старшие 32 —
  на вершине стека данных (а второй элемент стека — это уже "использованная"
  копия `x`, больше не нужна).
- `swap drop` — **важный момент**, на котором легко ошибиться (и ровно здесь была
  ошибка в одной из первых версий файла): после цикла стек `[T(верх) S(низ)]`,
  то есть старшее слово **уже** на вершине. `drop` без `swap` убрал бы именно
  старшее слово, а не устаревшую копию `x`. `swap drop` делает правильно: меняет
  местами, затем убирает то, что оказалось сверху (старую копию `x`), оставляя
  старшее слово произведения на вершине.
- `if mul_sat_checklow` снимает старшее слово; если оно равно нулю — переход на
  проверку младшего слова (возможно, переполнения нет). Если не равно нулю —
  переполнение гарантировано, выполнение проваливается на `0xCCCCCCCC` и прыжок
  на `mul_sat_done`.
- `mul_sat_checklow`: `a` кладёт младшее слово произведения (из регистра `A`) на
  стек. `dup -if mul_sat_ok` проверяет его знаковый бит: если оно неотрицательно —
  результат укладывается в диапазон `int32`, переходим на `mul_sat_ok` с этим
  значением на стеке как итоговым ответом. Если бит знака установлен (младшее
  слово "отрицательное") — значит настоящее произведение `>= 2^31`, это тоже
  переполнение: `drop 0xCCCCCCCC` заменяет результат на сигнальное значение.
- `mul_sat_ok`/`mul_sat_done` — пустая метка `mul_sat_ok` просто проваливается в
  `mul_sat_done`, которая содержит единственную инструкцию `;` — настоящий
  возврат из процедуры. Переходы `<label> ;` на `mul_sat_done` — это прыжки
  (`Jump`), а не вызовы, поэтому они не трогают стек возврата, и финальный `;`
  корректно возвращает управление туда, откуда `mul_sat` была изначально вызвана
  (через `call`, то есть просто по имени `mul_sat` в основном потоке).
