# Объяснение кода: `bracket-validator.s` (m68k)

Программа проверяет корректность вложенности скобок `()`, `[]`, `{}` в строке,
прочитанной через порт ввода. Прочие символы игнорируются, пустая строка валидна.
Результат — `1` (валидно), `-1` (невалидно) или `0xCCCCCCCC` (строка длиннее
буфера `0x40`) — записывается в порт вывода.

Алгоритм — классическая проверка сбалансированности скобок через **явный стек**,
реализованный вручную в памяти (регистр `A2` — указатель вершины этого стека),
отдельно от аппаратного стека вызовов (`A7`), который используется только для
`jsr`/`rts`.

## Секция данных

```asm
    .data

input_addr:        .word  0x80          ; адрес порта ввода
output_addr:       .word  0x84          ; адрес порта вывода
call_stack_top:    .word  0x600         ; вершина стека вызовов (A7)
bracket_stack_top: .word  0x400         ; вершина стека скобок (A2)
```

- `input_addr` / `output_addr` — не сами порты, а ячейки, хранящие *значения*
  `0x80`/`0x84` (адреса memory-mapped IO портов). Чтобы получить адрес порта в
  регистр, число сначала читается из этой ячейки, а потом используется как адрес.
- `call_stack_top` — начальный адрес аппаратного стека вызовов (`A7`). M68k не
  инициализирует `A7` сам, поэтому стартовое значение нужно задать явно, иначе
  `jsr`/`rts` будут работать с мусором.
- `bracket_stack_top` — начальный адрес **второго**, отдельного стека: сюда
  кладутся коды открывающих скобок, которые ещё не закрыты. Он не связан со
  стеком вызовов — это чисто наша структура данных для алгоритма.

## Секция кода

```asm
    .text
    .org     0x90                       ; код размещаем за зоной memory-mapped IO
```

`.org 0x90` сдвигает начало инструкций на адрес `0x90`, чтобы код не попал в
зону `0x80–0x87`, аппаратно отведённую под memory-mapped IO (иначе — повреждение
памяти, как уже бывало в других вариантах без такого сдвига).

## Инициализация (`_start`)

```asm
_start:
    movea.l  call_stack_top, A7
    movea.l  (A7), A7

    movea.l  input_addr, A0
    movea.l  (A0), A0

    movea.l  output_addr, A1
    movea.l  (A1), A1

    movea.l  bracket_stack_top, A2
    movea.l  (A2), A2

    move.l   0, D5                      ; глубина стека скобок
    move.l   0, D6                      ; флаг несовпадения
    move.l   0, D7                      ; счётчик прочитанных символов строки
```

Каждая пара `movea.l <константа>, Rn` + `movea.l (Rn), Rn` — стандартный приём:
первая строка кладёт в регистр **адрес ячейки** (саму константу-указатель, например
`0x600`), вторая читает **значение по этому адресу** (там лежит то же число,
записанное `.word`). В итоге:

| Регистр | Значение после инициализации | Назначение |
|---|---|---|
| `A7` | `0x600` | вершина стека вызовов |
| `A0` | `0x80`  | адрес порта ввода |
| `A1` | `0x84`  | адрес порта вывода |
| `A2` | `0x400` | вершина (пустого) стека скобок |

Дальше заводятся три регистра-счётчика:

- `D5` — сколько открывающих скобок сейчас лежит в стеке (не закрыто);
- `D6` — флаг ошибки: `0` — пока всё верно, `1` — найдено нарушение;
- `D7` — сколько символов уже прочитано в текущей строке (контроль переполнения).

## Главный цикл чтения строки

```asm
read_loop:
    cmp.l    0x40, D7                   ; лимит длины строки (buf_size)
    bge      overflow

    move.l   (A0), D0                   ; следующий символ входного потока
    cmp.l    10, D0                     ; '\n' -- конец строки
    beq      finish

    add.l    1, D7
    jsr      process_char
    jmp      read_loop
```

- `cmp.l 0x40, D7` вычисляет `D7 − 0x40` и выставляет флаги; `bge` переходит на
  `overflow`, если `D7 ≥ 0x40` (64) — то есть прочитано 64 символа без перевода
  строки (`buf_size = 0x40` по спецификации варианта).
- `move.l (A0), D0` читает **следующее** значение из порта ввода (адрес — в
  `A0`). У симулятора порт ввода — очередь: каждое обращение `(A0)` выдаёт
  следующий элемент списка `memory_mapped_io: 0x80: [...]` из yaml-конфига.
- `cmp.l 10, D0` + `beq finish` — если символ равен коду `10` (`'\n'`), строка
  закончилась, переходим считать итог.
- Иначе: увеличиваем счётчик символов (`D7 += 1`), вызываем `process_char` для
  текущего символа (`D0`), и безусловно прыгаем обратно на начало цикла.

## Подсчёт результата и единая точка выхода

```asm
finish:
    cmp.l    0, D6
    bne      invalid
    cmp.l    0, D5                      ; остались непарные открывающие скобки
    bne      invalid

    move.l   1, D2
    jmp      write_result

invalid:
    move.l   -1, D2
    jmp      write_result

overflow:
    move.l   0xCCCCCCCC, D2

write_result:
    move.l   D2, (A1)
    halt
```

- `finish`: если `D6 ≠ 0` (во время разбора уже зафиксирована ошибка) **или**
  `D5 ≠ 0` (остались непарные открывающие скобки) — строка невалидна, `D2 ← -1`.
  Иначе — валидна, `D2 ← 1`.
- `overflow`: `D2 ← 0xCCCCCCCC` — специальное значение «результат невозможно
  вычислить» по общему правилу всех вариантов `wrench`. Явный `jmp` сюда не нужен
  — следующая строка (`write_result`) идёт сразу после.
- `write_result`: записывает `D2` в порт вывода (адрес — в `A1`) и останавливает
  машину (`halt`). Это **единственная** точка `halt` в программе — сюда сходятся
  все три исхода (валидно / невалидно / переполнение).

## Классификация символа (`process_char`)

```asm
process_char:
    cmp.l    '(', D0
    beq      process_char_open
    cmp.l    '[', D0
    beq      process_char_open
    cmp.l    '{', D0
    beq      process_char_open
    cmp.l    ')', D0
    beq      process_char_close
    cmp.l    ']', D0
    beq      process_char_close
    cmp.l    '}', D0
    beq      process_char_close
    rts

process_char_open:
    jsr      push_open
    rts

process_char_close:
    jsr      check_close
    rts
```

Поочерёдно сравниваем `D0` (текущий символ) с кодами скобок (символьные
литералы `'…'` транслятор сам превращает в ASCII-код):

- совпало с `(`, `[` или `{` → `process_char_open` → вызов `push_open`
  (положить скобку в стек);
- совпало с `)`, `]` или `}` → `process_char_close` → вызов `check_close`
  (снять со стека и сравнить пару);
- иначе (любой другой символ, например буква) — `rts` без действий: прочие
  символы по условию задачи игнорируются.

## Работа со стеком скобок

```asm
push_open:
    move.l   D0, -(A2)
    add.l    1, D5
    rts
```

- `-(A2)` — адресация с **предекрементом**: сначала `A2` уменьшается на 4
  (размер `long`), затем по новому адресу записывается `D0`. Классический
  push — `A2` всегда указывает на последний положенный элемент (вершину стека).
- `add.l 1, D5` — увеличиваем счётчик глубины стека.

```asm
check_close:
    cmp.l    0, D5
    bne      check_close_pop
    move.l   1, D6                      ; закрывающая скобка без пары
    rts

check_close_pop:
    move.l   (A2)+, D1
    sub.l    1, D5

    cmp.l    ')', D0
    bne      check_close_bracket
    cmp.l    '(', D1
    beq      check_close_ok
    jmp      check_close_bad

check_close_bracket:
    cmp.l    ']', D0
    bne      check_close_brace
    cmp.l    '[', D1
    beq      check_close_ok
    jmp      check_close_bad

check_close_brace:
    cmp.l    '{', D1                    ; D0 здесь гарантированно '}'
    beq      check_close_ok

check_close_bad:
    move.l   1, D6

check_close_ok:
    rts
```

- Сначала проверяем, пуст ли стек (`D5 = 0`). Если пуст — закрывающая скобка
  без пары: `D6 ← 1` и выход (снимать нечего).
- Если не пуст (`check_close_pop`): `(A2)+` — адресация с **постинкрементом**:
  читаем значение по текущему адресу `A2` в `D1`, затем `A2` увеличивается на 4.
  Это pop — снимаем верхний элемент стека (ранее положенную открывающую скобку).
  Счётчик глубины уменьшается (`D5 -= 1`).
- Дальше — цепочка проверок «какая именно закрывающая скобка в `D0`» →
  сравнение снятого `D1` с ожидаемой парой:
  - `D0 = ')'` → ожидаем `D1 = '('`;
  - `D0 = ']'` → ожидаем `D1 = '['`;
  - иначе (гарантированно `D0 = '}'`, других вариантов не осталось) → ожидаем
    `D1 = '{'`.
- Совпало → `check_close_ok` (`rts`). Не совпало → `check_close_bad`: `D6 ← 1`,
  и без явного перехода проваливаемся в `check_close_ok` — общую точку выхода
  как для успеха, так и для ошибки.

## Логика кода

1. **Инициализация.** Настраиваются три регистра-указателя (`A7` — стек
   вызовов, `A0`/`A1` — порты ввода/вывода) и один вспомогательный стек скобок
   (`A2`), плюс три регистра-счётчика: `D5` (глубина стека скобок), `D6` (флаг
   «найдено нарушение»), `D7` (длина прочитанной строки).
2. **Основной цикл** читает входной поток символ за символом через порт `0x80`,
   пока не встретит `'\n'` или не превысит лимит длины строки `0x40` (тогда
   сразу идёт на `overflow`). Каждый непустой символ передаётся в
   `process_char`.
3. **`process_char`** классифицирует символ: открывающая скобка → `push_open`
   (кладёт её в стек скобок, `D5++`); закрывающая скобка → `check_close` (если
   стек пуст — сразу ошибка; иначе снимает верхний элемент, `D5--`, и сравнивает
   его с ожидаемой парой для текущей закрывающей скобки — если не совпало,
   выставляет `D6 ← 1`); любой другой символ — игнорируется.
4. **После окончания строки** (`finish`) итог определяется двумя проверками:
   если `D6 ≠ 0` (было явное несовпадение пары) или `D5 ≠ 0` (остались непарные
   открывающие скобки) — строка невалидна (`D2 ← -1`); иначе — валидна
   (`D2 ← 1`).
5. **Общий эпилог** (`write_result`) всегда одинаков для всех трёх исходов
   (валидно / невалидно / переполнение буфера): записывает итоговое значение
   `D2` в порт вывода `0x84` и останавливает машину — единственный `halt` в
   программе.

Код демонстрирует требуемые для варианта m68k приёмы: несколько режимов
адресации (immediate, прямая регистровая, индирект с offset `0`,
пре-декремент/пост-инкремент для стека) и вложенные вызовы процедур
(`_start → process_char → push_open/check_close`) с использованием явного
стека.
